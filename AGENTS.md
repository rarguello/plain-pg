# AGENTS.md — rules for `plain-pg`

Guidance for any agent (OpenCode, Codex) or person working in this repo.

## What this is

PostgreSQL streaming replication on OpenShift using **plain Kubernetes objects**.
No operator, no CRDs, no console.

- 1 primary (`postgresql-0`) + 1 hot standby (`postgresql-1`).
- Image: **PostgreSQL 18 on UBI** (`registry.redhat.io/rhel10/postgresql-18`),
  pinned by digest.
- The role is decided by the `postgresql-role` ConfigMap (`PRIMARY_POD`).
- Manual failover, plus an optional automatic failover CronJob with verifiable
  pod-level fencing.
- Logical backups (`pg_dump`) as a CronJob.
- Optional read autoscaling (HPA) paired with the `postgresql-r` Service.
- Kustomize, a `Makefile`, and a test suite in `tests/`.

## Hard rules

1. **No operators, no CRDs.** Core objects only.
2. **No secrets in git.** The Secret is generated by
   `scripts/generate-secret.sh` and lives in `secrets/` (gitignored).
3. **The image must be UBI** (`registry.redhat.io/...`), pinned by digest.
4. **Test namespace: `postgresql-lab`.** Do not touch other namespaces.
5. **Do not hardcode a StorageClass** unless it is unavoidable (and document it).
6. **Everything documented was tested.** No untested procedures.
7. **Idempotency:** every script must survive being run twice.
8. **Watch the labels.** Auxiliary pods (backup, failover, load) must not carry
   `app.kubernetes.io/name: postgresql` or `instance: postgresql`, or they become
   endpoints of the database Services.

## Conventions

- Documentation and comments in **English**. Identifiers and log messages in
  English too.
- Resource prefix: `postgresql-`.
- Common labels: `app.kubernetes.io/{name,instance,part-of,component}`.
- Real `PGDATA`: `/var/lib/pgsql/data/userdata`.
- Template changes require deleting pods by hand (`updateStrategy: OnDelete`).
- Keep it small. This repo is meant to be read in one sitting: prefer deleting a
  script or a section over adding one.

## Workflow

1. Read `docs/` before proposing changes.
2. One commit per logical step, clear message.
3. Apply to the cluster and **verify with evidence**.
4. Run `./tests/run-all.sh rapido` before closing a step; the full
   `./tests/run-all.sh` before a release.
5. Update the affected documentation in the same commit.
6. Have Codex review each milestone (correction of YAML/scripts, split-brain or
   data-loss risks, idempotency, consistency with these rules).

## Commands

```bash
./scripts/deploy.sh                  # deploy (lab overlay)
./scripts/verify-replication.sh      # check replication
./scripts/failover-manual.sh         # promote a replica
./scripts/backup-now.sh              # manual backup
./scripts/restore-backup.sh <dump>   # restore into a new database
./scripts/read-load.sh 180 12        # read load (HPA demo)
./scripts/teardown.sh                # destroy
./tests/run-all.sh rapido            # non-destructive tests
make lint                            # shellcheck + kustomize + embedded scripts
```

## Forbidden

- Installing PostgreSQL operators (OLM).
- Using `docker.io/library/postgres` in deployable manifests.
- Real credentials or another cluster's StorageClass in the repo.
- Documenting something that was not tested.
